## 1.2 评分维度映射（4 维度逐一针对性设计）

| 维度 | 权重 | 本项目的针对性设计 |
|---|---|---|
| 创新性与技术含量 | 30% | ① **技能文件化架构**：六个技能不是硬编码，而是 `skills/*.json` 工作流文件，引擎运行时加载——改技能不改代码；② **状态机执行引擎**：每一步 pending→running→done/failed 全程留痕（对齐图谱 L10 字段冻结表），支持取消/重跑/人工确认；③ **双 Provider 降级**：真实 LLM（OpenAI 兼容）+ 内置确定性 Mock，无 key 也能完整演示；④ **流式对话（SSE）+ 技能路由**：自由聊天时模型自动识别意图挂载技能；⑤ **工件（Artifact）系统**：结构化产物可预览、可下载（JSON/CSV/Markdown） |

| 市场潜力与社会价值 | 30% | 跨境电商与独立开发者出海是确定性的大市场；中小创作者缺的不是产品，是**让海外用户看懂的语言与内容**。OneCrew 把出海内容的门槛从"会英语、懂海外平台、懂各文化禁忌"降到"会描述自己的产品"。社会价值：给中小创作者全球化平权的工具——大公司有 agency，一人公司有 OneCrew |
| 海外落地可行性 | 10% | 产品本身即为海外场景而生：输出直接面向 X/Twitter、Instagram、TikTok、LinkedIn、Product Hunt 的平台原生格式与多语言（EN/ES/JA…）；技术栈（Node.js + 静态前端 + OpenAI 兼容 API）在海外云（Vercel/Railway/Fly.io）零改造可部署 |

# 第二部分 · 市场与竞品调研

> 说明：以下为基于公开产品形态的桌面调研（desk research），用于定位差异，非引证报告。

## 2.1 形态参照：豆包 / 即梦

豆包与即梦验证了"对话式智能体"的三个用户习惯：**输入框即入口**（不教用户用什么菜单）、**技能卡片即引导**（看一眼就知道能干嘛、点一下就能跑）、**产物即回复**（生成的不是解释，是能直接用的东西）。本项目沿用该交互范式，但把"闲聊/成片生成"换成**面向真实业务任务的流水线执行**。

## 2.2 竞品格局与空白

| 竞品 | 强项 | 缺口（一人公司视角） |
|---|---|---|
| Copy.ai / Jasper | 海外营销文案生成、模板丰富 | 通用营销向，不懂"中国产品出海"的文化转译；按席位订阅贵 |
| Buffer / Hootsuite AI | 排期与发布 | 只做"排期"这一环，前面的市场判断、品牌声音、合规是空白 |
| 通用对话助手（ChatGPT/Claude 等） | 能力强 | 每次从零聊天，没有技能沉淀、没有工作流留痕、没有结构化工件产出 |
| 国内出海 SaaS（各类 ERP/选品工具） | 供应链/数据强 | 内容创作环节几乎缺位 |

**空白点**：没有一款产品以"一人公司"为主体，把出海内容的**研究→定位→创作→排期→合规**全链条装进一个可复核的智能体。OneCrew 卡位这个空白。

## 2.3 目标用户画像

1. 跨境电商独立站卖家（有产品，缺海外内容）；
2. 独立开发者 / 独立 App 作者（上架 Product Hunt、发 X 官宣是刚需）；
3. 小微品牌出海操盘手（一人身兼数职）。

# 第三部分 · 设计开发文档（按图谱 06 模板 11 节）

## 0 · 文档头

OneCrew · 一人出海 AIGC 内容官 · v1 · 2026-08-31 · 作者：AI · 读者：AI + 参赛评审

## 1 · 需求理解

- **一句话**：一个豆包式对话智能体：你说一个产品，它像一支六人内容小队一样跑完「市场快研 → 品牌声音 → 多平台文案 → 视觉提示词 → 内容日历 → 合规体检」，产出一套可直接落地的出海内容包，每一步可看、可停、可复核、可导出。
- **用户故事**：作为一人公司卖家，我想输入"我的产品是 XXX"就能得到面向海外各平台的多语言文案和发布计划，以便一个人完成过去需要一个内容团队才能完成的出海推广。
- **边界（v1 明确不做）**：不生成图片/视频/3D 成片（只产出**图像提示词**与文案，提示词可供 Midjourney/即梦等工具二次使用——这是"创作辅助"，与赛道"不做成片内容"的约束一致）；不做真实社媒发布（产出+排期，发布由人执行）；不做多用户账号体系；不做支付。

## 2 · 形态选择

- 形态：**A4 Web 应用**（React 单页 + Node.js 后端），图谱 05 选型 P1-3 + P2-4。
- 理由：评审要"可运行、可演示"——Web 一条命令跑起来，截图/录屏/现场演示都最顺；对话式 UI 用 React 组件化最快。
- 升级路径：v2 可包成微信小程序（B1）或部署海外云（K2），核心引擎（`server/`）与技能文件零改动复用。

### 3.1 六大技能定义

| 技能 | 输入 | 输出（工件） |
|---|---|---|
| `market-scan` 市场快研 | 产品描述、可选目标市场 | 市场报告（推荐市场+平台+竞品维度+差异化角度），Markdown 工件 |
| `brand-voice` 品牌声音官 | 产品描述 | `brand_voice.json`（人设/语气/禁用词/口号候选），JSON 工件 |
| `copy-studio` 文案流水线 | 产品描述 + 目标市场/语言 | 5 平台原生文案包（X/Instagram/TikTok 脚本/LinkedIn/Product Hunt），Markdown 工件 |
| `visual-prompt` 提示词工坊 | 产品描述 + 场景 | Midjourney/即梦/SD 三套图像提示词（含负向提示词与参数），Markdown 工件 |
| `content-calendar` 内容日历 | 产品描述 + 市场节奏 | 7 天发布计划（日期/平台/主题/文案钩子/标签），**CSV 工件可下载** |
| `local-check` 合规体检 | 目标市场 + 内容要点 | 文化禁忌/广告法合规/节日日历检查清单，Markdown 工件 |

- **v1 主流程**：打开应用 → 选示例或直接说"我的产品是保温杯，想卖日本" → 路由器识别意图 → 挂载技能跑流水线（或点技能卡直调） → 右侧面板看到每一步进度与日志 → 产物逐个生成并出现在工件区 → 一键导出。

## 4 · 技术选型（图谱 05 六决策点）

| 决策点 | 选择 | 理由 |
|---|---|---|
| P1 前端 | React 18 + Vite | 对话流式渲染 + 运行面板组件化最快，评审观感最好 |
| P2 后端 | Node.js + Express（零构建依赖） | 前后端同语言，单机 `node server/index.js` 即跑，1 天交付最稳 |
| P3 存储 | JSON 文件库（`data/`） | 零安装；runs 逐个落盘天然满足"可复核、可留证"，评审可直接打开文件查看 |
| P4 文件 | 本地 `exports/` 目录 | 导出的 Markdown/CSV 即交付证据 |
| P5 部署 | 本地一键启动（`npm start`） | 演示优先；升级路径：静态托管 + 容器 |
| P6 第三方 LLM | OpenAI 兼容接口（`api.b.ai/v1`，模型 `deepseek-v4-flash`，key 复用本地已有额度，仅存服务端 `.env`）+ **内置 MockProvider 降级** | 已有额度零新增成本；断网/无 key 时 Mock 确定性产出，保证评审永不空场 |

- **密钥管理**：API key 只在 `server/.env`（服务端环境变量），前端零密钥；`.env.example` 提供模板（铁律：密钥绝不进前端）。

## 5 · 页面/模块设计

- **左栏**：会话列表（新建/切换/删除）+ 技能卡片入口（六技能一键直调）+ 运行记录入口。
- **中栏（对话区）**：豆包式消息流，支持 Markdown 渲染与打字机流式输出；欢迎页展示示例引导词（点击即填）；技能卡片悬浮展示说明。
- **右栏（工作台）**：两个 Tab——「运行」展示当前 run 的步骤时间线（每步状态/耗时/日志摘要，等待确认时出现批准/驳回按钮，支持取消/重跑）；「工件」展示生成的产物列表（点击预览，支持下载）。

## 6 · 数据模型（★ 字段冻结表，对齐图谱 L10）

`agents`（由 `agents/onecrew.agent.json` 加载）：
```json
{ "agent_id": "onecrew", "name": "OneCrew 出海内容官", "description": "…",
  "steps": [ { "step_id": "s1", "name": "市场快研", "type": "skill", "skill": "market-scan", "config": {} },
             { "step_id": "s4", "name": "市场确认", "type": "confirm", "config": {} } ],
  "status": 1, "created_at": 1756... }
```

`runs`（每 run 一个 JSON 文件 `data/runs/<run_id>.json`）：
```json
{ "run_id": "r_xxx", "agent_id": "onecrew", "session_id": "s_xxx", "user_id": "local",
  "status": "pending|running|waiting_confirm|done|failed|canceled",
  "current_step": "s2", "mode": "real|mock",
  "params": { "product": "…", "market": "…", "language": "en" },
  "steps": [ { "step_id": "s1", "name": "市场快研", "type": "skill", "status": "done", "started_at": 0, "ended_at": 0, "detail": "…", "artifacts": ["a_xxx"] } ],
  "artifacts": [ { "artifact_id": "a_xxx", "name": "市场快研报告", "type": "markdown", "path": "exports/…", "created_at": 0 } ],
  "result": { "summary": "…" }, "error": null, "created_at": 0 }
```

`sessions`（`data/sessions/<session_id>.json`）：
```json
{ "session_id": "s_xxx", "title": "保温杯出海", "messages": [ { "id": "m_xxx", "role": "user|assistant", "content": "…", "run_id": null, "artifacts": [], "created_at": 0 } ], "created_at": 0 }
```

- 索引（简化为文件清单 + 内存 Map）：runs 按 created_at 倒序；sessions 按 updated_at 倒序。
- **冻结**：runs 不可变（重跑生成新 run，旧 run 保留作审计）；confirm 步骤必等人工；密钥只在服务端。

## 7 · 接口契约（★）

统一返回：SSE 事件流（chat/run 执行）与 JSON（其余）。错误格式 `{ "error": { "code": "…", "message": "…" } }`。

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| GET | `/api/health` | — | `{ok, mode(real/mock), model}` |
| GET | `/api/agents` | — | agents 数组 |
| POST | `/api/sessions` | `{title?}` | session 对象 |
| GET | `/api/sessions` | — | 会话列表（摘要） |
| GET | `/api/sessions/:id` | — | 完整会话 |
| DELETE | `/api/sessions/:id` | — | `{ok}` |
| POST | `/api/chat`（SSE） | `{session_id, message}` | 事件：`start`→`token`(增量)→`step`(进度)→`artifact`(产物)→`run`(run 元数据)→`done`/`error` |
| POST | `/api/agents/:id/run` | `{session_id?, params}` | `{run_id}` 并后台启动 |
| GET | `/api/runs` | `?session_id=&limit=` | run 摘要列表 |
| GET | `/api/runs/:id` | — | run 完整对象（步骤/日志/工件） |
| POST | `/api/runs/:id/confirm` | `{approve: bool}` | 确认点处理：批准继续 / 驳回 canceled |
| POST | `/api/runs/:id/cancel` | — | canceled |
| POST | `/api/runs/:id/retry` | — | 新 run_id（复用 params） |
| GET | `/api/artifacts/:id` | — | `{name, type, content}` |
| GET | `/api/artifacts/:id/download` | — | 文件流（CSV/MD/JSON） |

- **SSE 事件约定**（前端渲染依据，冻结）：`event: <name>\ndata: <json>\n\n`；`token` 携带 `{delta}`；`step` 携带 `{run_id, step_id, step_name, status, detail}`；`artifact` 携带 `{artifact_id, name, type, preview}`。

## 8 · 外部依赖

| 依赖 | 用途 | 密钥 | 费用 | 失败怎么办 |
|---|---|---|---|---|
| OpenAI 兼容 LLM（api.b.ai · deepseek-v4-flash） | 全部生成能力 | 服务端 `.env` | 复用本地已有额度，零新增 | 自动降级 MockProvider，界面明示"演示模式" |

## 9 · 异常与边界

| 场景 | 处理 |
|---|---|
| 无 API key / 网络断 | 自动切 Mock，UI 顶部横幅提示"演示模式" |
| LLM 超时（>90s/步） | 该步 failed + 原因记录，可重跑 |
| 输入为空/超长（>4000 字） | 前端校验 + 后端截断保护 |
| confirm 等待中用户关闭页面 | run 落盘保持 waiting_confirm，重进可继续批准 |
| 用户连点发送 | 前端节流；后端每会话串行处理 |
| 生成内容含敏感词 | H8 闸：本地敏感词表拦截，替换为提示（演示级，v2 接云端审核） |
| CSV 特殊字符 | 标准 CSV 转义（逗号/引号/换行），UTF-8 BOM 保证 Excel 打开不乱码 |
| 并发写同一 JSON | Node 单进程串行 + 写时原子替换（tmp+rename） |

## 10 · 开发计划（骨架先行，1 天内）

1. **骨架**：Express 服务 + React 壳 + 健康检查打通 → 验收：`npm start` 打开页面。
2. **引擎**：Provider 双实现 + 技能加载器 + 单技能执行 + SSE → 验收：mock 模式跑通 `brand-voice`。
3. **六技能 + 路由**：技能文件 + 提示词 + 意图路由 → 验收：自由对话命中技能。
4. **工作流 + 状态机 + 确认点**：`going-global-kit` 串联 → 验收：waiting_confirm 批准/驳回均正确。
5. **工件系统**：预览 + CSV/MD/JSON 导出 → 验收：Excel 打开 CSV 不乱码。
6. **留痕与复核**：runs 落盘 + 运行面板 → 验收：重进应用能看到历史 run 全日志。
7. **真实模式联调 + 截图 + 文档**。

## 11 · 验收标准（逐条）

1. `npm start` 一条命令启动，浏览器打开即见豆包式界面。
2. 发"我的产品是保温杯，想卖日本" → 流式回复 + 命中技能 → 右栏出现步骤进度 → 产物生成。
3. 点六个技能卡任意直调 → 均产出对应工件。
4. 一键工作流跑到"市场确认" → 步骤挂起显示确认按钮 → 驳回则 canceled、批准则继续 → 最终 done。
5. 取消运行中任务 → 状态 canceled 且留痕。
6. 关掉服务重启 → 历史会话与 run 全部还在（可复核）。
7. 拔掉 key 重启 → 演示模式横幅出现，全流程仍可跑。
8. CSV 日历用 Excel 打开中文不乱码、列不串行。
9. 无密钥暴露：前端源码 grep 不到任何 key。
